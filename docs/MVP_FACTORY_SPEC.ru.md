## Место в FactoryOS
Показывать отдельный раздел **MVP Factory** под Agent Office, визуально отличающийся от **Content Factory**. Не создавать второй автономный планировщик. Повторно использовать существующие события Relay, идентичности воркеров, одобрения, ссылки на GitHub Issue/PR и журнал аудита.

## Роли и передачи работы
1. **MVP Manager** (оркестратор, а не новая подписка на LLM): отвечает за очередь и статус, выбирает следующую подходящую задачу, фиксирует доказательства.
2. **Product Analyst / Spec Writer**: превращает идею в проблему, покупателя, предложение, объём работ, метрику успеха, зависимости и эксперимент по проверке на 24–72 часа.
3. **Claude Builder**: назначается только после одобрения спецификации, пишет веб-превью в изолированной ветке и открывает черновой PR. Никакого двойного владения задачей воркерами.
4. **QA / Security**: независимо проверяет тесты, секреты, права доступа к маршрутам и готовность. Отсутствие CI — это BLOCKED, а не зелёный статус.
5. **Deploy Agent**: предлагает превью на существующей бесплатной инфраструктуре; никаких новых облачных ресурсов и публичного деплоя без одобрения владельца.
6. **Content Factory**: получает маркетинговый бриф только после проверки превью и одобрения владельца; никогда не публикует автоматически.

## Машина состояний
`idea -> researching -> spec_draft -> spec_review -> build_queued -> building -> qa_review -> preview_ready -> owner_review -> validated | rejected`.
В состояние `blocked` можно перейти из любого незавершающего состояния, указав причину, время и источник.
Не переводить состояние дальше на основании одного утверждения LLM; нужна конкретная ссылка-доказательство или одобренное действие. «Неизвестно» не значит «выполнено».

## Приёмка и проверки
- Панель интерфейса показывает три пилота и чётко помечает статус seed/demo.
- Отдельно от Content Factory и Agent Office; локализация EN/UK/RU при интеграции.
- Переход по клику к каноническим GitHub Issues; никаких фальшивых таймеров, расхода токенов или сигналов жизни воркеров.
- Один реальный пилот демонстрирует путь: спецификация -> PR с кодом -> CI -> проверенное превью -> решение владельца.
- Безопасность и CI остаются обязательными. Никаких трат, сообщений, публикаций или изменений инфраструктуры без одобрения.
