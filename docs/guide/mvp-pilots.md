# MVP Factory и пилоты: как это работает

> Сверено с кодом и `ROADMAP.md` 2026-11-16. Если панель показывает другое, верна панель: значит, гайд устарел.

## Что это

**MVP Factory** (в меню группа «MVP Builder») — реестр маленьких продуктов-проверок. Каждая идея проходит одни и те же этапы, и каждый шаг вперёд подтверждается ссылкой-доказательством. Финальное решение «подтверждено» или «отклонено» принимаете только вы.

Код: `mvp_factory.py` (реестр и API `/api/mvp-factory`), спецификация: `docs/MVP_FACTORY_SPEC.md`, эпик #186.

## Как это работает по шагам

1. **Идея** попадает в реестр как проект на этапе `idea`.
2. **Этапы** идут строго по одному вперёд: `idea` → `researching` → `spec_draft` → `spec_review` → `build_queued` → `building` → `qa_review` → `preview_ready` → `owner_review` → `validated` или `rejected`.
3. **Доказательство.** Каждый шаг вперёд требует ссылку: issue, PR, коммит, запуск CI на GitHub или страницу `/static/...`. Фраза ИИ «готово» доказательством не считается. Проверяется только форма ссылки, не её смысл, и система прямо это пишет.
4. **Агенты** могут вести проект только через исследование и спецификацию. В сборку, превью, вердикт и отказ им переходить запрещено.
5. **Ваше решение.** `validated` и `rejected` ставит только владелец.

Внутри карточки проекта есть «автопилот» агентов: Researcher готовит исследование и 3 варианта, Spec Writer пишет спецификацию, затем всё останавливается на вашем одобрении спецификации. По умолчанию он выключен и работает на бесплатном ключе Gemini.

## Цикл улучшения V1 → V2 (#270)

Модуль `mvp_evolution.py`, страница `static/mvp-factory/evolution.html`. Этап проекта он не меняет.

1. Отзывы сохраняются только с явным согласием. Имя участника не хранится, только хеш.
2. Цель первой когорты — 10 настоящих содержательных отзывов, следующей — 100. Демо-данные помечены и не считаются.
3. Из отзывов собираются темы: сколько людей «за», что против, уверенность (меньше 3 человек — «недостаточно»).
4. Предложение V2 ссылается на конкретные отзывы и имеет тест приёмки. Одобряете или отклоняете только вы.
5. Передача сборщику создаёт ровно одну задачу в Relay. «Выпущено» — только со ссылкой на слитый PR или коммит.
6. Выпуск V2 делаете вы, потом исходные участники проверяют новую версию.

Сделано (T-631): версионированные контракты 13 логических ролей в `mvp_contracts.py`. Для каждой роли записано, что ей разрешено, что она получает и что сдаёт, сколько у неё повторов и какой таймаут, и какие доказательства должен иметь завершённый запуск. Каждая роль работает на одном из пяти существующих агентов. Ни одна роль не может одобрять, выпускать, публиковать или тратить деньги.

Ещё не сделано: приём задач сборщиком через события Relay (T-632), события использования внутри пилотов (T-633).

## A/B-эксперименты

Сделано (T-608–T-610, #348): в проекте можно создать эксперимент ровно с двумя ветками, A сверху и B снизу.

- Режим `SEGMENT_COMPARISON` сравнивает аудитории и **никогда не объявляет победителя**. `CONTROLLED_AB` пока только черновик: случайного распределения нет.
- Превью каждой ветки одобряете вы. По кнопке создаётся один черновик в Content Factory на ветку, без публикации.
- Метрики, расходы и рассылки здесь не записываются. Итог выбираете вы: `continue_a`, `continue_b`, `both`, `iterate`, `pivot` или `stop`.

## Что делаете вы

- Одобряете спецификацию перед сборкой и ставите итоговый вердикт.
- Сами связываетесь с людьми: FactoryOS никому ничего не отправляет.
- Одобряете предложения V2 и выпуск новой версии.

## Где смотреть

- Меню → **MVP Builder** → **Проекты**: строки проектов, кнопка открыть страницу MVP Factory (`/static/mvp-factory/index.html`).
- В карточке проекта: ссылка на превью, «Product Evolution · V1→V2», а для #189 — «AI Release Guardian».
- Задачи для вас: Worker Center → «Ваши задачи».

## Ограничения

- Ни одного полного прогона «спецификация → PR → CI → превью → ваше решение» ещё не было.
- Ничего не публикуется, не тратит деньги и не уходит наружу без вашего одобрения.
- Реестр не запускает воркеров сам: исполнитель только очередь Relay.
