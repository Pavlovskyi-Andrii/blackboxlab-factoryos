# MVP Factory і пілоти: як це працює

> Звірено з кодом і `ROADMAP.md` 2026-11-16. Якщо панель показує інше, правильна панель: отже, гайд застарів.

## Що це

**MVP Factory** (у меню група «MVP Builder») — реєстр маленьких продуктів-перевірок. Кожна ідея проходить ті самі етапи, і кожен крок уперед підтверджується посиланням-доказом. Остаточне рішення «підтверджено» чи «відхилено» ухвалюєте лише ви.

Код: `mvp_factory.py` (реєстр і API `/api/mvp-factory`), специфікація: `docs/MVP_FACTORY_SPEC.md`, епік #186.

## Як це працює по кроках

1. **Ідея** потрапляє в реєстр як проєкт на етапі `idea`.
2. **Етапи** йдуть суворо по одному вперед: `idea` → `researching` → `spec_draft` → `spec_review` → `build_queued` → `building` → `qa_review` → `preview_ready` → `owner_review` → `validated` або `rejected`.
3. **Доказ.** Кожен крок уперед потребує посилання: issue, PR, коміт, запуск CI на GitHub або сторінку `/static/...`. Фраза ШІ «готово» доказом не вважається. Перевіряється лише форма посилання, не його зміст, і система прямо це пише.
4. **Агенти** можуть вести проєкт лише через дослідження і специфікацію. Переходити у збирання, превʼю, вердикт і відмову їм заборонено.
5. **Ваше рішення.** `validated` і `rejected` ставить лише власник.

У картці проєкту є «автопілот» агентів: Researcher готує дослідження і 3 варіанти, Spec Writer пише специфікацію, потім усе зупиняється на вашому схваленні специфікації. За замовчуванням він вимкнений і працює на безкоштовному ключі Gemini.

## Цикл покращення V1 → V2 (#270)

Модуль `mvp_evolution.py`, сторінка `static/mvp-factory/evolution.html`. Етап проєкту він не змінює.

1. Відгуки зберігаються лише з явною згодою. Імʼя учасника не зберігається, лише хеш.
2. Ціль першої когорти — 10 справжніх змістовних відгуків, наступної — 100. Демо-дані позначені і не рахуються.
3. З відгуків збираються теми: скільки людей «за», що проти, впевненість (менше 3 людей — «недостатньо»).
4. Пропозиція V2 посилається на конкретні відгуки і має тест приймання. Схвалюєте чи відхиляєте лише ви.
5. Передача збирачу створює рівно одну задачу в Relay. «Випущено» — лише з посиланням на злитий PR або коміт.
6. Випуск V2 робите ви, потім початкові учасники перевіряють нову версію.

Зроблено (T-631): версіоновані контракти 13 логічних ролей у `mvp_contracts.py`. Для кожної ролі записано, що їй дозволено, що вона отримує і що здає, скільки в неї повторів і який таймаут, і які докази має мати завершений запуск. Кожна роль працює на одному з п'яти наявних агентів. Жодна роль не може схвалювати, випускати, публікувати чи витрачати гроші.

Зроблено (T-633): підрахунок використання за згодою на сторінках пілотів (MyCast, MyBrief, Decision Memory). Сторінка спершу питає; після «Дозволити» зберігаються три дати на відвідувача під випадковим кодом, який лежить у його браузері: вперше відкрив, вперше скористався, повернувся іншого дня. Без імені, e-mail, адреси та вмісту сторінки, без сторонньої аналітики. Відвідувач може переглянути й видалити запис на тій самій сторінці. Рядки воронки «активували / використали / повернулися» рахуються за цими записами, вручну їх більше ввести не можна. Вимикач: `FACTORY_USAGE_EVENTS=0` зупиняє нові події; перегляд і видалення працюють далі.

Ще не зроблено: приймання задач збирачем через події Relay (T-632).

## A/B-експерименти

Зроблено (T-608–T-610, #348): у проєкті можна створити експеримент рівно з двома гілками, A згори і B знизу.

- Режим `SEGMENT_COMPARISON` порівнює аудиторії і **ніколи не оголошує переможця**. `CONTROLLED_AB` поки лише чернетка: випадкового розподілу немає.
- Превʼю кожної гілки схвалюєте ви. За кнопкою створюється одна чернетка в Content Factory на гілку, без публікації.
- Метрики, витрати і розсилки тут не записуються. Підсумок обираєте ви: `continue_a`, `continue_b`, `both`, `iterate`, `pivot` або `stop`.

## Що робите ви

- Схвалюєте специфікацію перед збиранням і ставите підсумковий вердикт.
- Самі звʼязуєтеся з людьми: FactoryOS нікому нічого не надсилає.
- Схвалюєте пропозиції V2 і випуск нової версії.

## Де дивитися

- Меню → **MVP Builder** → **Проєкти**: рядки проєктів, кнопка відкрити сторінку MVP Factory (`/static/mvp-factory/index.html`).
- У картці проєкту: посилання на превʼю, «Product Evolution · V1→V2», а для #189 — «AI Release Guardian».
- Задачі для вас: Worker Center → «Ваші задачі».

## Обмеження

- Жодного повного прогону «специфікація → PR → CI → превʼю → ваше рішення» ще не було.
- Ніщо не публікується, не витрачає гроші і не йде назовні без вашого схвалення.
- Реєстр не запускає воркерів сам: виконавець лише черга Relay.
