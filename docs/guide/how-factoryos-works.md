## 1. Из чего состоит система

| Часть | Что это | Где живёт |
|---|---|---|
| **Панель FactoryOS** | Сайт, где вы всё видите и одобряете | Render, `blackboxlab-factoryos.onrender.com` |
| **Сервер** | FastAPI-приложение (`app.py` и модули рядом) | Render. Деплой идёт только после зелёного CI на `main` |
| **EC2-воркер** | Отдельная машина, где агенты реально работают: Claude, браузер, MyCast | AWS EC2, цикл `autopilot/` |
| **GitHub** | Код, задачи (issues), PR, проверки CI | `blackboxlab-factoryos` |
| **Telegram-бот** | Ставит задачи агентам и присылает результаты и MyCast | Relay-бот |
| **Notion** | Концепции, решения, исследования, память проекта | Notion workspace |

## 2. Кто что делает

- **Вы (владелец).** Ставите цели и приоритеты. Одобряете публикации, расходы, крупные релизы и всё, что уходит наружу. Без вашего «да» ничего не публикуется.
- **Claude.** Пишет код в отдельной ветке, открывает PR, запускает тесты, делает ревью архитектуры и выполняет задачи из Telegram через Relay.
- **ChatGPT / Codex.** Пишут спецификации и прототипы и делают автоматическое ревью PR. Блокирующие замечания Codex исправляются до слияния.
- **Gemini.** Бесплатный помощник: делает исследования, черновики и документацию, озвучивает MyCast.
- **Браузерный агент.** Читает страницы в браузере на EC2, в том числе под сохранённой сессией. Он только читает и ничего не публикует.

## 3. Как задача проходит путь

1. **Задача.** Вы пишете её в Telegram или создаёте issue на GitHub.
2. **Relay.** Задача становится тикетом `R-xxxx` со статусом `queued`. Это значит «назначено», но ещё не «выполняется».
3. **Claim.** Воркер на EC2 забирает тикет, и статус становится `claimed`, потом `running`. Только с этого момента работа реально идёт.
4. **Ветка и PR.** Агент делает изменения в отдельной ветке и открывает PR.
5. **CI.** GitHub Actions прогоняет проверки. Красный CI означает, что сливать нельзя.
6. **Ревью.** Codex и/или человек проверяют PR. Блокирующие замечания исправляются.
7. **Слияние → деплой.** После слияния в `main` Render сам деплоит новую версию, но только после зелёного CI.
8. **Ответ в Telegram.** Вы получаете итог: PR, ссылку или понятную причину ошибки.

**Если задача упала по лимиту.** Claude получает до 60 ходов и 30 минут на один прогон. Если этого не хватило, бот так и пишет. Разбейте задачу на шаги или нажмите Retry.

## 5. Контент-фабрика

1. **Бренд-стратегия.** 7 шагов: цель → распаковка → аудитория → тон → столпы → воронка → CTA. Одобренные шаги собираются в **Master Brief**. Каждый агент контента получает свою часть брифа.
2. **План на 30 дней.** Из плана создаются задачи. Задача, созданная из строки плана, помнит, к какому бренду она относится.
3. **Производство.** Сценарий → голос → видео → финиш (субтитры, звук, безопасные зоны).
4. **Review.** Вы одобряете или отправляете на переделку.
5. **Publish.** Отдельное явное действие после одобрения. Автопубликации нет.
6. **Performance.** Только реальные метрики с платформ. Нет метрик — нет «обучения».

## 6. MVP Builder

- У каждого проекта есть стадия: идея → исследование → спецификация → сборка → превью → проверка владельцем → validated/rejected.
- Стадию двигает только событие с доказательством: ссылкой на PR, коммит, CI или артефакт.
- Финальные стадии (`validated` / `rejected`) ставите только вы.
- **A/B Tester** пока только спецификация (PR #347, разбор в #348). Сравнение двух аудиторий — это «сравнение сегментов», а не рандомизированный A/B-тест.

## 7. MyCast

- Ваш личный выпуск приходит в Telegram до 06:00 по Киеву. Подробнее в гайде «MyCast для владельца».
- Сайт для слушателей: `mycast.pro`. Вход через Telegram, Google нужен только для календаря.
- Рефералка: друг получает +7 дней сразу. Пригласивший получает +7 только после первого реального выпуска друга.

## 8. Правила, которые нельзя обойти

- Публикация, расходы и любые сообщения третьим лицам требуют вашего явного одобрения.
- Платные вызовы моделей не включаются автоматически. У Content Brain есть бюджетный лимит.
- Секреты не пишутся в чат, не попадают в репозиторий и не показываются на экране. Они хранятся в Render или в зашифрованном хранилище (vault).
- В `main` не пушат напрямую: только через PR с зелёным CI.
- Тесты нельзя выключать или ослаблять ради зелёного CI.
- Метрики, квитанции публикаций и успех деплоя нельзя выдумывать. Где данных нет, пишется «нет данных».

## 9. Где смотреть, если что-то не так

| Вопрос | Где ответ |
|---|---|
| Что сейчас делают агенты? | Консоль владельца → Telegram-задачи. Ещё есть Агенты и Воркеры |
| Почему задача упала? | Сообщение в Telegram (там прямая причина), центр ошибок |
| Что изменилось в коде? | GitHub → PR и `DECISIONS.md` |
| Что в плане? | Build Progress (`ROADMAP.md`) |
| Сколько потрачено на Actions? | GitHub → Billing. CI запускается только на PR и `main`, скриншоты только на `main` |
