# Документація: сторінка «Завдання команди» (`Team Tasks`)

Цей посібник призначений для Власника й описує, як влаштована сторінка «Завдання команди», що означають елементи на ній, статуси задач і джерела даних.

## 1. Звідки беруться дані

Модель даних збирає інформацію виключно шляхом читання таких джерел:

#### GitHub API

- **Issues**: задачі репозиторію. Виконавець (agent) визначається за першим рядком опису (`Owner: Claude`, `Owner: ChatGPT`, `Owner: Gemini`).
- **Pull Requests**: запити на злиття. Виконавець визначається за префіксом гілки (`claude/`, `chatgpt/`, `gemini/`).
- **Check Runs (CI)**: статуси автотестів і перевірок CI на головних комітах відкритих PR.

#### EC2-знімок / смуги агентів (Lanes / Heartbeat)

- Статус активності агентів (онлайн/офлайн) і час останнього «пульсу» (`heartbeat_age_seconds`).

#### ROADMAP.md

- Задачі з позначкою `[HUMAN]`, що чекають на дії Власника.

#### Owner Desk (картки рішень Власника)

- Картки рішень, що пояснюють кроки для розблокування або затвердження задач.

## 2. Що означають плитки агентів

На сторінці є плитки для кожного агента (**Claude**, **ChatGPT**, **Gemini**) і для **Власника (Owner)**.

Кожна плитка містить:
- **Індикатор онлайн-статусу**: показує, чи активний агент зараз, на основі heartbeat з EC2.
- **Поточна задача (Current)**: активна задача в роботі (`in_progress`, `review`, `ci_failed`).
- **Наступна задача (Next)**: перша задача в черзі (`queued`).
- **Остання виконана (Last Done)**: нещодавно завершена задача (`done`).
- **Лічильники за статусами**: кількість задач у різних станах і загальна кількість виконаних задач за останні 7 днів (`done_7d`).

## 3. Статуси задач і прогрес

Шкала прогресу показує етап виконання задачі:

| Статус | Прогрес | Значення |
|---|---|---|
| `queued` | 0% | Задача в черзі, ще не взята в роботу. |
| `blocked` | 0% | Задачу заблоковано міткою `blocked`, залежностями або умовою Власника. |
| `waiting_owner` | 0% | Задача чекає на дію Власника (`ROADMAP [HUMAN]` або картка рішень). |
| `in_progress` | 40% | Агент виконує задачу (створено Draft PR). |
| `ci_failed` | 60% | PR готовий або в чернетці, але перевірки CI впали. |
| `review` | 85% | PR готовий і чекає на перевірку (рев'ю). |
| `done` | 100% | Задачу завершено (PR змерджено або Issue закрито). |

## 4. Причини та уточнення статусів (`reason`)

Для точної діагностики поруч зі статусом виводиться текстова причина (нижче — підписи з українського інтерфейсу панелі):

- **«CI впав — виконавець має виправити» (`ci_failed`)** — упали перевірки CI в GitHub Actions.
- **«чекаємо результат CI» (`ci_running`)** — перевірки CI ще тривають на коміті PR.
- **«чекає перевірки Claude» (`awaiting_review`)** — PR готовий до перевірки рецензентом або власником.
- **«чернетка PR — робота йде» (`draft_pr`)** — відкрито Draft PR, робота триває.
- **«чекає Gemini (заходить кожні 5 хвилин…)» (`gemini_loop`)** — задача Gemini з міткою `gemini`; цикл Gemini в GitHub Actions заходить по неї приблизно раз на 5 хвилин.
- **«ще не розпочато» (`not_started`)** — задача в черзі, роботу ще не розпочато.
- **«потрібна ваша дія» / «потрібне ваше рішення» (`owner_action` / `owner_decision`)** — потрібне рішення або дія Власника.
- **«заблоковано (мітка blocked)» (`blocked_label`)** — на Issue стоїть мітка `blocked`.
- **«чекає на #N — рішення за вами» (`depends`)** — задача чекає на закриття пов'язаних issues/tasks (`Depends: #...`).
- **«чекає вашого схвалення» (`owner_gate`)** — у заголовку є обмеження на старт (наприклад, `CONDITIONAL` або `только после`).
- **«зайнято іншим виконавцем» (`blocked_by_other`)** — задачу заблоковано з іншої причини, наприклад її вже взяв інший виконавець.

## 5. Вкладки та Queue Keeper (Зберігач черги)

- **Вкладки агентів**: перемикають відображення між усіма задачами команди та детальними списками окремих учасників (Claude, ChatGPT, Gemini, Owner).
- **Queue Keeper (Зберігач черги #231)**: визначає, які відкриті задачі готові до взяття в роботу просто зараз (ціль за замовчуванням — 10 готових задач). Рахується лише для лінії Claude. Автоматично розподіляє задачі на три групи, перелічені нижче.

Групи Queue Keeper:
- `ready` — повністю готові до старту;
- `blocked` — заблоковані (мітки, незакриті `Depends:`, умови власника);
- `in_review` — уже мають відкритий або змерджений PR.

## 6. Кнопка «Оновити зараз»

- Дані про задачі кешуються, щоб зменшити навантаження на GitHub API, з періодом оновлення **180 секунд (TTL)**.
- Натискання кнопки **«Оновити зараз»** примусово запитує свіжі дані з GitHub і зі знімка EC2.
- Щоб не перевищити ліміти API, встановлено мінімальний інтервал повторного оновлення — **20 секунд** (`min_refresh`).
