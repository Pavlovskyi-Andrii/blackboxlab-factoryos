## 1. Dependencies

pip-audit resolved 31 packages from `requirements.txt` (unpinned `>=` ranges) on Python 3.9 and found 20 advisories in 6 packages:

| Package | Resolved | Fixed in (highest listed) |
|---|---|---|
| starlette | 0.49.3 | 1.3.1 |
| python-multipart | 0.0.20 | 0.0.31 |
| urllib3 | 2.6.3 | 2.8.0 |
| anyio | 4.12.1 | 4.14.2 |
| requests | 2.32.5 | 2.33.0 |
| python-dotenv | 1.2.1 | 1.2.2 |

Caveat: Render installs `requirements.txt` on every deploy without a pinned Python version, so production may resolve newer versions. starlette is capped by FastAPI's own requirement, so an old starlette in production is likely. **Not confirmed** — confirm with `pip freeze` in a Render shell or by pinning.

Recommendation (separate PR, CI-gated): pin direct and transitive versions (a lock file or `==` constraints), raise `python-multipart`, `urllib3`, `requests`, `anyio`, `python-dotenv` to fixed versions, move FastAPI to a release that allows a fixed starlette, and add `pip-audit` as a CI step so new advisories fail a PR.

**Follow-up 2026-11-02:** the CI run on Python 3.13 installed starlette 1.10.0, python-multipart 0.0.33, urllib3 2.8.0, anyio 4.16.0, requests 2.34.2, python-dotenv 1.2.4 — all fixed. Every fixed release needs Python ≥ 3.10, so the advisories only apply to the Python 3.9 resolution. Done: `.python-version` = 3.13 (production = CI), security floors with a `python_version >= "3.10"` marker in `requirements.txt` (the worker's 3.9 test venv stays installable), and `pip-audit` as a CI step.

## 2. Secrets in git history

Two commits on 2026-10-26 put presigned S3 GET URLs (generated from temporary STS credentials) into a workflow file. Each URL embeds the temporary access key id and session token but not the secret access key, and was signed for 3600 s; both expired on 2026-10-26 around 20:22–20:24 UTC. A presigned URL cannot be used to sign new requests. Risk today: none known.

Recommendation: owner may delete the stale branch `bootstrap/aws-worker-transfer-20261026` (Claude does not delete branches). Future bootstrap transfers should keep presigned URLs out of committed files (pass them as workflow inputs or secrets).

## 3. Code patterns (bandit)

103 findings in non-test files (420 including tests). Manually triaged the medium ones; see the summary table. SQL findings are false positives. The `urlopen` calls need a short review of where each URL comes from; the RSS collector and outbound webhooks are the candidates.

## Not covered (blind spots)

- No dynamic testing, no authentication/authorization review of every FastAPI route, no review of the browser JavaScript, no infrastructure (Render/AWS IAM) review.
- Static tools cannot prove the absence of vulnerabilities.
- GitHub secret scanning for private repositories is a paid feature and was not enabled.

## Next steps

1. Dependency pinning + upgrades + `pip-audit` in CI (fixes finding 1, prevents regressions).
2. Route-level auth review (owner / viewer / worker tokens) — highest-value manual check for this app.
3. SSRF review of the `urlopen` call sites; `defusedxml` for RSS.
4. Re-run this baseline after 1–3 and keep the before/after as the sample report for #101.
