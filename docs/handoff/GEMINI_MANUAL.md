# Gemini в FactoryOS — руководство исполнителя

**Для кого:** Gemini как агент-программист (Jules или Gemini Code Assist), подключённый к репозиторию `Pavlovskyi-Andrii/blackboxlab-factoryos` на GitHub.
**Кто главный:** владелец ставит цели и приоритеты. Claude — координатор разработки: ставит задачи, проверяет и вливает PR. ChatGPT — второй исполнитель. Ты — третий.

## 1. Что такое FactoryOS (коротко)
- **Сайт** (`app.py`, FastAPI, Python 3.13) на Render: дашборд, API, Relay (очередь задач для агентов), «Ваши задачи» (инструкции владельцу), MyCast (утренний подкаст).
- **Воркер** на AWS EC2 (`autopilot/`): Claude Code по подписке берёт задачи из `ROADMAP.md`, пушит в ветку `autopilot/aws-worker`. **Эту папку и эту ветку не трогай.**
- **CI** (`.github/workflows/ci.yml`): компиляция, smoke-тесты, регрессионные тесты, `pip-audit`, скриншоты интерфейса.
- **Где ты:** работаешь на своих серверах Google в копии репозитория. К EC2 и Render доступа у тебя нет и не нужно.

## 2. Как к тебе приходят задачи
1. Claude создаёт GitHub Issue. Первая строка тела — `Owner: Gemini`. FactoryOS сам подтягивает такие задачи в Worker Center, владелец их видит.
2. Владелец или Claude ставит на issue метку `jules` (для Jules) или пишет тебе номер issue.
3. Бери только задачи с `Owner: Gemini`. Если задача неясна или пересекается с открытым PR — напиши комментарий в issue и не начинай.

## 3. Как выполнять
1. Ветка `gemini/<короткое-имя>` от свежего `main`.
2. Сначала прочитай код вокруг изменения и существующие тесты для этой области (`test_*.py`, их список — в `ci.yml`).
3. Делай минимальное изменение, которое закрывает критерий «Готово» из issue. Не переделывай чужой код «заодно».
4. Пиши тесты. Тест маршрута API — **через настоящее ASGI-приложение** (`factory.app(scope, receive, send)`), как `OwnerDeskWorkerMiddlewareTest` в `test_worker_token_binding.py`. Прямой вызов функции маршрута пропускает общий фильтр авторизации — так 2 ноября пропустили баг.
5. Интерфейс (`static/index.html`): строки на EN/UK/RU одновременно, `test_locale_parity.py` должен проходить.
6. Открой PR в `main` и сошлись на issue (`Closes #N` только если задача полностью готова).

## 4. Нельзя
- Пушить в `main` / `autopilot/aws-worker`, force-push, удалять ветки, вливать PR.
- Менять `autopilot/`, `.github/workflows/`, `CLAUDE.md`, `AGENTS.md`, `.python-version` без прямого указания в issue.
- Писать в код, тесты, issue или PR значения секретов (ключи API, токены, пароли). Ключ Gemini у сайта — переменная `FACTORY_GEMINI_API_KEY` в Render; в тестах используй поддельные значения.
- Включать платное: платные API и тарифы, `FACTORY_VIDEO_ADAPTER=gemini` (платная генерация видео), рекламу, реальные публикации, письма людям.
- Ослаблять тесты, авторизацию или одобрение публикаций ради зелёного CI.
- Писать «готово», если что-то не проверено: так и пиши «не проверено».

## 5. Описание PR (обязательно)
- **Что сделано** и какой issue / задача ROADMAP.
- **Команды, которые ты реально запускал**, и их результат. Если не смог запустить smoke-тесты — так и напиши.
- **Что не проверено.**
- Скриншоты, если менялся интерфейс (CI делает их сам — задача `ui-screenshots`).

## 6. Что дальше
Claude проверяет PR: CI, код, тесты, при необходимости скриншоты. Замечания — комментарием в PR; исправляй в той же ветке. После проверки Claude вливает сам.
