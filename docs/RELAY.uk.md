# FactoryOS Relay

Relay — це мобільний шар вхідних і завдань для FactoryOS.

## Telegram

Після того як звичайне прив'язування Telegram до FactoryOS виконано:

- будь-який звичайний текст, посилання, голосове повідомлення, відео, документ або фото перетворюється на постійний тікет Relay;
- `/tasks` або `/relay` показує активні тікети;
- `/new <text>` створює тікет явно;
- `/work R-0001`, `/need R-0001`, `/done R-0001` і `/inbox R-0001` змінюють стан тікета;
- кожен новий тікет має вбудовані кнопки In progress (у роботі), Need you (потрібні ви), Done (готово) та Inbox (вхідні);
- звичайний текст і далі передається в старий міст до агента, тож Relay додає надійну історію завдань, нічого не ламаючи в обробці.

Повторні доставки оновлень від Telegram відкидаються як дублікати за update id.

## Мобільна дошка

Відкрийте `/relay` на хості FactoryOS, увійшовши в систему. На дошці є колонки:

- Inbox (вхідні)
- In progress (у роботі)
- Need you (потрібні ви)
- Done (готово)

Дошка оновлюється автоматично й дає змогу створювати та переміщувати тікети.

## Дані

Тікети зберігаються в `DATA_DIR/relay.json` на наявному постійному диску FactoryOS. Кожен тікет зберігає метадані джерела, нотатки та незмінну історію подій. Для вкладень зберігаються file id з Telegram, тому голосові повідомлення, відео й документи не губляться навіть до того, як буде додано розшифрування чи аналіз.

## Межа оператора

У тікетах Relay є заготовка для стану Operator. Виконання дій у браузері та застосунках буде побудовано поверх тікетів. Будь-яка покупка чи оплата має вимагати явного підтвердження власника перед фінальною зовнішньою дією.
