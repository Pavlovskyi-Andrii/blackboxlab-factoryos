# Google Calendar для MyCast — налаштування власником (доступ лише на читання)

Мета: слухач натискає «Підключити Google Календар» на сторінці MyCast, надає доступ **лише на читання**, і наприкінці
випуску звучать сьогоднішні зустрічі та дні народження друзів. У календар нічого не записується.

Стан коду: кнопка підключення та OAuth-процес робляться лише після виконання кроків 1–6 (їм потрібен секрет клієнта).
До того сторінка чесно показує «не підключено».

## Обмеження, які треба знати заздалегідь (виправлено після ревю Codex у #332)
- **Статус публікації та верифікація — це різні речі.** Статус (*Testing* / *In production*) задається
  в розділі Audience; верифікація — це перевірка застосунку з боку Google.
- *Testing*: підключитися можуть лише додані вами тестові користувачі (не більше 100), і **їхній доступ до календаря спливає кожні 7 днів**
  (Google видає 7-денні refresh-токени застосункам у режимі Testing, які запитують чутливі права). Щотижневе перепідключення —
  це очікувана поведінка, а не помилка.
- *In production* без верифікації: спробувати може будь-хто, але він побачить попередження «неперевірений застосунок», а Google обмежує
  кількість користувачів, які можуть надати неперевіреному застосунку чутливе право.
- *In production* з верифікацією: без попередження і без щотижневого спливання доступу.
- **Статус діє на весь проєкт.** Якщо проєкт, у якому налаштовано вхід у MyCast через Google, уже
  *In production*, **не** перемикайте його в *Testing*: усі, кого немає в тестовому списку, втратять вхід через Google.
- Для верифікації потрібен **власний домен**: MyCast використовує **mycast.pro** (куплено 2026-11-13).

## Кроки
1. **Проєкт** — https://console.cloud.google.com → виберіть проєкт, у якому налаштовано вхід у MyCast через Google
  (клієнт, що стоїть за `FACTORY_GOOGLE_CLIENT_ID`).
2. **Увімкніть API** — ☰ → APIs & Services → Library → "Google Calendar API" → Enable.
3. **Право лише на читання** — ☰ → Google Auth Platform → Data Access → Add or remove scopes →
  `https://www.googleapis.com/auth/calendar.readonly` → Update → Save.
  Цього достатньо і для зустрічей, і для календаря Google «Дні народження» (Birthdays).
4. **Redirect URI** — Google Auth Platform → Clients → клієнт типу *Web application* → Authorized redirect URIs →
  додайте `https://mycast.pro/api/mycast/calendar/callback` (і для старої адреси
  `https://blackboxlab-factoryos.onrender.com/api/mycast/calendar/callback`). В **Authorized JavaScript origins**
  додайте `https://mycast.pro` (вхід через Google на новому домені). Збережіть.
5. **Секрет клієнта в Render** — у тому самому клієнті скопіюйте *Client secret* (або натисніть *Add secret*) → Render → сервіс
  `blackboxlab-factoryos` → Environment → `FACTORY_GOOGLE_CLIENT_SECRET` → Save. Ніколи не вставляйте його в чат чи в Git.
6. **Тестові користувачі** — Google Auth Platform → Audience. Лише якщо статус уже *Testing*: Test users → додайте до
  100 адрес Gmail. Якщо статус *In production*, нічого не змінюйте (див. обмеження вище).
7. **Брендинг** — Google Auth Platform → Branding: назва застосунку (MyCast), email підтримки, домашня сторінка `https://mycast.pro`,
  політика конфіденційності `https://mycast.pro/privacy`, умови використання `https://mycast.pro/terms`, дозволений домен `mycast.pro`.
8. **Верифікація (з власним доменом)** — підтвердьте домен у Google Search Console, потім Google Auth Platform →
  Verification Center → надішліть заявку: коротке відео, де видно екран згоди і те, як використовуються дані календаря, та
  обґрунтування для `calendar.readonly`. Опишіть реальний шлях даних (ревю Codex у #333): «MyCast читає лише сьогоднішні події
  та календар Birthdays у момент підготовки випуску для слухача. Назви й час подій передаються в Anthropic
  Claude (пише сценарій випуску) і Google Gemini (озвучує його); аудіо надсилається в особистий Telegram-чат
  слухача. MyCast не зберігає дані календаря, не використовує їх ні для чого іншого і не продає та не передає їх
  нікому іншому». Це збігається з https://mycast.pro/privacy.

Коли кроки 1–6 виконано, напишіть Claude «готово»: наступним етапом буде зроблено кнопку підключення, OAuth-процес і блок календаря у випуску.
